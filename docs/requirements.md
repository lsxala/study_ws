# 软件测试学习路线导航网站需求文档

版本：v0.1  
日期：2026-05-28  
状态：活文档，后续可以随着学习理解和产品方向持续调整

## 1. 项目定位

这是一个面向软件测试零基础学习者的学习路线导航网站。

网站的第一目标不是一次性做成完整课程平台，而是帮助学习者回答三个问题：

1. 我现在应该从哪里开始学？
2. 下一个知识点是什么？
3. 学完一个知识点后，我怎么判断自己真的懂了？

第一版优先做“路线清晰、解释友好、能持续扩展”的学习导航，不追求复杂登录、后端系统或完整课程商业化能力。

## 2. 目标用户

### 主要用户

零基础或接近零基础的软件测试学习者。

用户特点：

- 不熟悉软件测试行业术语。
- 可能不了解前端、后端、接口、数据库、自动化等概念。
- 希望知道学习顺序，而不是只看到一堆知识点。
- 需要简单例子、实操任务和阶段反馈。

### 内容表达原则

每个知识点默认按照下面的顺序讲：

1. 这是什么？
2. 为什么要学？
3. 工作里怎么用？
4. 我可以做什么小练习？
5. 学到什么程度算过关？

术语必须尽量解释，不默认用户已经懂。

## 3. 产品目标

### 第一阶段目标

构建一个本地可运行的软件测试学习路线导航网站。

第一阶段要做到：

- 能看到完整学习路线。
- 能按阶段查看知识点。
- 能打开一个知识点详情。
- 能标记学习状态。
- 内容对零基础用户友好。

### 暂不追求

第一阶段暂不做：

- 用户登录。
- 云端同步。
- 复杂后台管理。
- 在线代码运行环境。
- 付费课程系统。
- 多人协作学习。

这些能力可以作为后续扩展，不进入第一版核心范围。

## 4. 技术选型

第一版采用：

- React
- Vite
- TypeScript
- Tailwind CSS
- React Router
- lucide-react
- localStorage

技术选择理由：

- React + Vite 适合快速构建交互式学习网站。
- TypeScript 帮助后续维护学习路线数据结构。
- Tailwind CSS 适合快速做出清晰、统一的页面。
- React Router 支持路线页、知识点详情页等页面切换。
- localStorage 可以先保存本地学习进度，避免过早引入后端。

## 6. 学习路线初稿

路线来自当前思维导图，但会重新组织成更适合零基础学习的顺序。

### 阶段 1：测试基础

目标：知道软件测试是什么，以及测试人员在项目中做什么。

包含方向：

- 软件测试是什么
- 测试流程
- 测试用例
- 功能测试
- 缺陷提交
- 常见测试方法
- Web 项目测试基础

### 阶段 2：计算机和工具基础

目标：补齐做测试必须知道的基础工具。

包含方向：

- Linux 基础
- Shell 常用命令
- 数据库基础
- MySQL 常用操作
- Git 基础
- 浏览器开发者工具

### 阶段 3：Python 编程基础

目标：能看懂和编写简单测试脚本。

包含方向：

- 基本数据类型
- 列表、元组、字典、集合
- 条件判断和循环
- 函数
- 文件操作
- 异常处理
- 面向对象入门
- 常用内置函数

### 阶段 4：接口测试

目标：理解软件系统之间如何通信，并能做基础接口测试。

包含方向：

- 接口是什么
- HTTP 基础
- 请求和响应
- cookie、session、token
- Postman 使用
- 接口测试用例
- Python requests 接口测试

### 阶段 5：Web 自动化测试

目标：能用工具模拟用户操作网页。

包含方向：

- Selenium 环境搭建
- 元素定位
- 页面操作
- 等待机制
- Web 自动化测试脚本
- 简单 Web 项目自动化实战

### 阶段 6：APP 自动化测试

目标：理解移动端自动化测试的基本流程。

包含方向：

- Appium 环境搭建
- UIAutomator 元素定位
- APP 自动化基础脚本
- H5 / 小程序自动化概念

### 阶段 7：性能测试

目标：知道性能测试关注什么，以及如何用工具进行基础压测。

包含方向：

- 性能测试是什么
- JMeter 环境搭建
- JMeter 脚本开发
- 性能场景设计
- 性能数据分析
- 性能测试报告

### 阶段 8：持续集成和测试开发

目标：理解测试如何接入团队工程流程。

包含方向：

- Git 仓库使用
- Jenkins 基础
- 自动化测试在 Docker 中运行
- Flask mock 系统
- 简单测试平台

## 7. 知识点数据结构草案

每个知识点建议包含：

- id：唯一标识
- title：知识点标题
- stage：所属阶段
- level：入门 / 基础 / 进阶
- summary：一句话解释
- beginnerExplanation：给零基础学习者的解释
- whyItMatters：为什么要学
- workScenario：工作场景例子
- prerequisites：前置知识
- practice：最小练习
- doneCriteria：学会判断标准
- resources：参考资料
- status：未开始 / 学习中 / 已完成

## 8. 第一版 MVP 范围

第一版最小可用版本建议包含：

- 首页展示完整学习阶段。
- 阶段卡片展示学习目标和知识点数量。
- 知识点列表支持点击进入详情。
- 知识点详情展示“是什么、为什么、怎么用、练习、完成标准”。
- 本地保存学习状态。
- 页面适配桌面浏览器。

## 9. 交互原则

- 首页不要像广告页，要直接进入学习路线。
- 默认展示下一步该学什么。
- 每个页面都要让用户知道自己在哪个阶段。
- 不用大量专业术语堆叠。
- 操作按钮要明确，例如“开始学习”“标记为已完成”“返回路线”。
- 后续可以加入进度条，但第一版不强制复杂统计。

## 10. 分支和迭代建议

建议一个功能一个分支：

- codex/chore-project-bootstrap
- codex/docs-learning-site-requirements
- codex/feature-learning-map
- codex/feature-topic-detail
- codex/feature-local-progress
- codex/feature-search-filter
- codex/feature-quiz

每个功能分支合入前至少确认：

- 页面能正常打开。
- 没有明显控制台错误。
- 主要交互可以使用。
- 内容没有明显超出零基础学习者理解范围。

## 11. Agent 和 Skill 约束建议
